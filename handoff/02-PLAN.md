# 分阶段执行计划：dsh-table

按当前状态选择最重要的开放链路，不机械重做已成立部分。先形成真实可用的小闭环，再扩展全部场景；不能无限增加文档和评审代替实现。

## T0：接手复核与真实入口

1. 核对根目录、工作树、上一轮候选包和安装版本。
2. 依据目标DSH公开声明确认服务key、路由注册、Client入口、Node/UI边界及实际权限。
3. 在隔离profile真实加载安装包，完成一条会话操作；模型和宿主依赖缺口分别报告。

退出：有真实宿主与桌面加载证据；没有条件则明确BLOCKED并继续可独立领域工作。

## T1：连续主助理与正确意图

1. recent messages、结构化决定、任务引用与项目brief进入实际模型请求，按消息ID和cursor取最近记录，避免只取最早100条或按相同文字误删历史。
2. 所有主对话分支共享上下文组装，包括讨论、正常问答、任务变更和澄清回复。
3. 区分讨论/推荐/开工/否定/取消，支持语音式多意图和纠正；不默认猜第一个项目。
4. 明确模型/Agent provider与能力，缺服务显示事实，不用模板冒充真实助理。

退出：多轮指代、改要求、闲聊插队、超过历史分页后的连续性有独立验证。

## T2：任务主动维护与真实成果

1. 不选卡也先建立工作归属，匹配已有事项或创建适当任务；有据可查且避免重复卡。
2. 从所有开工入口走同一调度链路。worker实际读取授权材料并完成业务交付，记录真实执行身份。
3. 注册必要的查询、创建/更新、派发、结果回写工具或结构化协议；模型说建卡必须有数据库事实。
4. 验收按明确内容标准/用户决定处理，附反例；已运行/待审批/待验收任务不重复开工。
5. 结果通过持久Outbox投递主入口；普通工作直接推进，必要权限使用DSH原交互。
6. 项目根无效则阻塞。成果关联Run，续作不覆盖前轮唯一成果。

退出：U1和U4真实成立，含修改目标、用户告知完成和外部文件变化的局部核对。

## T3：队列、停止、继续和崩溃窗口

1. 持久队列与领取/受理记录原子一致；范围控制门禁按intent/run隔离。
2. Stop等待真实收敛；工具未退出保持stopping/unknown与槽位，子任务/job有正确owner。
3. 只停A时保留B；已停止卡的新一轮不被永久cancelled集合误杀。
4. 请求幂等覆盖实际执行次数和副作用，不只Run行数。
5. 重启查询真实受理/执行情况；无法确认则unknown。禁止所有running一律改todo后允许无条件重做。
6. 覆盖领取后未启动、受理后ACK丢失、结果提交前后、停止与完成竞态。

退出：U3及故障回归成立，旧结果不覆盖新一轮状态，已有成果保存。

## T4：记忆、预算与会话交接

1. 保存有来源的决定、目标、未决交互、结果与材料引用；区分个人、项目、任务作用域。
2. 交接数据实际进入新会话。真实创建/恢复并验证Session后再绑定；若使用自管消息则准确命名能力。
3. 对所有分支统一预算；裁剪后重新计算含提示尾注的完整输入，保留当前工作关键事实。
4. pending输入和结果交付不依赖旧主Session生命周期；用户无需手动换窗口。
5. 以大项目索引、长材料和多轮修改验证预算与检索，避免每轮全盘扫描。

退出：U5与长历史压力场景成立，不能只断言generation数字变化。

## T5：远程接入与日常体验

1. 与Remote Connect对齐公开接口/能力版本、host/profile和领域cursor。
2. Local/Remote Provider跑同一业务用例；Mac不回退本地执行。
3. 真实Mac DSH中验证U6、停止、待审批、重连与双端更新。
4. 先提供小范围可恢复试用，再按反馈修交互；操作说明必须符合真实界面。

退出：真实跨设备与用户故事有对应证据；Mac缺席只阻塞相应关卡。

## T6：发布准备与可维护交付

构建可追溯、源码/包/安装/运行版本一致；备份和冲突感知回滚成立；凭据/私有数据不进入公开材料；许可清楚；README命令真实可用；已知限制明确。Git提交、发布、服务改造仍需用户相应授权。

## 每轮选题与验收

优先影响数据、范围、假执行/假停止的问题，其次连续对话和真实宿主接线，再做视觉打磨。新问题使用稳定ID并进入03-STATE；当前计划覆盖目标不因一个问题已修而整体勾PASS。

详细控制场景沿用 [控制设计](../docs/CONTROL_AND_AUTONOMY.md)、[验证计划](../docs/AUTOMATED_VALIDATION_PLAN.md)、[144条规格](../validation/scenarios.json)。目录存在不表示场景已运行。
