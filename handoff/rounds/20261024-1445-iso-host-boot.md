## 3. 本轮实现与理由
| 文件/模块 | 改了什么 | 为什么这样改 | 替代方案/取舍 | 影响与回滚 |
| --- | --- | --- | --- | --- |
| src/index.ts | 工具注册全部改为真实 dsh-tools 契约：`output: { schema, render }`（raw 子集：required 仅允许 object 节点且为属性名数组）、执行入口 `execute(args)` 取代 `handler`；list 类工具返回包对象 `{projects}/{tasks}` 以保持 object 根 | 真实宿主注册时严格校验（缺失 output 抛 TypeError），执行后按 output.schema 校验返回值（ToolOutputError）；原写法导致 workbench 服务在真实宿主无法激活 | 经 defineTool 编译层适配：放弃（会引入对宿主内部 API 的依赖），直接对齐 raw register 契约 | 单文件回滚即可；无 schema/DB 变更 |
| src/index.ts | 路由挂载改为 `webServer.register({ kind: 'exact', path, handler })`：先收集后按 path 合并注册（宿主路由表不按方法键控，同 path GET/POST 必须合并并在 handler 内按 req.method 分发）；每路由复用宿主 `client-connection.admit` 鉴权围栏（服务缺席时仅允许回环）；raw req/res 适配（JSON body/query 解析、res.status/json 垫片） | 原 Express 风格 `webServer.get/post` 在真实宿主不存在，`typeof === 'function'` 守卫静默跳过全部 16 条路由（HTTP 全 404）；exact 路由优先于 /api 网关前缀，必须显式过 admit 否则绕过鉴权 | 保留 get/post 回退分支仅供既有测试桩；真实宿主只走 register 路径 | 回滚即还原该文件 |
| src/index.ts | systemPrompt 注入改为 `section({ name, order, text })`（text 为函数，动态有界上下文） | 真实 dsh-system-prompt 契约为 section()，原 addSection 为臆测 API，静默未生效 | 无 | 无 |
| src/index.ts | 新增 optionalService()：经 `ctx.reflect.get(name, false)` 动态读取可选宿主服务（agentRunner/sessionController） | cordis 禁止未声明 inject 的属性访问（抛 "cannot get property ... without inject"），原属性访问使 capabilities 500、chat 500、Worker 无法收敛 | 声明 inject：放弃（会使服务在缺席环境中永不激活） | 无 |
| tests/host_tool_contract.test.mjs（新增） | 真实宿主契约镜像：注册桩按 dsh-tools 规则校验（output/render/execute/schema 子集/required 类型规则），并对每个工具实际返回值按其 output.schema 校验 | 既有测试桩 `tools: { register: () => {} }` 无差别放行，UNIT 层无法拦截契约漂移——本轮 3 项缺陷全部漏网的原因 | 无 | 永久回归保护 |
| scripts/verify-host-iso.mjs（新增） | 隔离宿主 11 项端到端验证脚本（鉴权交换、项目/任务/能力披露/快照/聊天/建卡/执行/名册 client/Outbox），输出脱敏 JSON 证据 | 真实宿主证据需要可复现的独立 oracle，不能以手工 curl 截图代替 | 无 | 可重复执行 |
| handoff/.active.json | 占用锁创建并绑定 roundId | 并行写入协议要求 | 无 | 收尾时删除 |
| package.json（事故恢复） | 被 `npx asar extract-file` 误用覆写为运行时清单；已从候选包 tarball 原样恢复（SHA-256 0909a5b3...，与包内一致），并清除误释放的 desktop-runtime.json | 我方工具误用（extract-file 只接受两参，第三参被忽略并写入 CWD），非外部原因；如实记录 | 无 | 已恢复，`npm run build/typecheck/test` 全部正常 |
